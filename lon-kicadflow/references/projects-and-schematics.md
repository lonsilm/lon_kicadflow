# 建项与绘制原理图

绘制、添加或完善原理图时，必须先读取并执行 [逐器件详细中文注释规范](schematic-annotations.md)。说明文字全部中文，几乎每个实际器件均需有可唯一对应的具体用途、真实连接、关键参数和默认/正常状态解释；不能只写类别或把注释放在图外。

## 设计输入

从现有工程、BOM、手册和用户描述提取供电范围、具体器件型号/封装、I/O、接口、板框/层数/成本、制造与装配方式。仅询问确实缺失且影响架构的信息；合理假设可记录后继续。

建立可追溯架构：输入→保护/电源树→核心→启动/复位/时钟→接口→测试点。各电源列电压、电流依据、负载、时序和未确认项。不要按电容数量判断完整性。

## 创建工程

确认目标新目录不存在，或明确识别已有根入口。根 `.kicad_pro`、`.kicad_sch`、`.kicad_pcb` 同名，避免平行竞争入口。

1. 有合适官方模板时复制到新目录，更新名称、UUID、实例与路径并原生验证；保留许可。别把成品板复制后称为空白工程。
2. 无GUI可用本skill的 `new-project` 创建KiCad 8格式空项目，由已安装KiCad≥8跑网表/ERC/DRC验证。默认2层，按要求指定4/6/8层。不隐含制造规则或工作电路。
3. 官方API也可在授权的新项目/隔离目录建板。CLI通常没有完整“画原理图/新建项目”命令，不编造。

```text
python <SKILL>/scripts/kicad_ops.py new-project <新目录>/Controller --layers 4 --thickness 1.6 --cli <CLI>
```

项目按需使用 `sheets/`、`libraries/`、`models/`、`datasheets/`、`reports/`、`manufacturing/`；不强行生成所有空目录。

## 层次和画面

按功能分页：电源、核心、启动下载、接口、模拟、扩展、测试。根页引用子页；独立子页导出不能代替根网表。

- 定义网络名、页间接口与电源域；局部、全局、层次标签作用域不同。多实例子页尤其核对路径。
- 原理图通常采用50mil/1.27mm连接网格，以实际工程为准。视觉相触不保证电气连接，核对端点、结点、跨线和NC。
- 测试点接支路；画清主电流路径、连接器观察方向、启动和跳线默认状态。
- 根页添加引用时只改必要段，不重排所有原页。标题注释避免未经验证的长期“可量产/禁止投板”断言。

## 程序编辑现代原理图

`scripts/sexpr_read.py`解析结构并保留字符串区间，不验证电气语义。不用 `.*?\)` 抓嵌套符号，也不全局替换一个可能重复的网名。

从当前版本生成的已验证对象/库获取结构；定位确切节点→生成局部新节点→按原字符串字符区间替换→保持其它内容。字符区间不能直接当UTF-8字节区间。

关键结构：

- 根 `lib_symbols` 内含使用符号；引用 `lib_id` 必须可解析。
- 实例 `uuid`、`unit`、`at`、属性、pin UUID与 `instances/project/path` 要与根UUID/页路径一致。
- 多unit器件及电源unit不能丢失、重复；新增对象用新UUID，移动原对象保留身份。
- 继承符号可能用 `extends`，需解析有效定义，不能凭当前文件没看到pin认定无引脚。
- 引脚位置由符号pin坐标、实例旋转/镜像决定；实例中心不是连线端点。
- wire/junction/label实际坐标和作用域形成连接；图旁文字针表不形成电气连接。

完成一个元件：位号唯一、定义可解析、可渲染、值/封装/必要采购字段正确、根网表包含、网络与ERC符合预期，并有图内可见、准确对应位号和实际用途的详细中文注释。BOM里有一行不代表原理图存在，旁边有“滤波”等模糊文字也不代表注释合格。

## 常见变更与保护

### 只添加

“加去耦/LED/测试点”保留原有值、MPN、封装和网络，除非另有明确要求。列新位号/网络/作用；验证原 `(ref,pin)→net` 与原属性不变。不要擅自恢复用户删除的器件或占用刻意留空的位号。

### 删除或不引出

只删除明确对象及必要图形。连接器用户要求悬空就NC，不能为消除ERC接地。删外部支路不能断内部用途；全局标签改动检查根网表。

### 改封装/元数据

先看用户实际板上焊盘与订料。更正料号≠更换封装；只改原理图/库时不更新PCB，交付说明。旧BOM不能推翻用户有意更改的焊盘。

### 连接器重排

列允许集合和固定集合（电源地、启动、调试、PMIC、差分、NC、受保护已布线网），在允许触点中做双射，验证信号无重复/丢失、固定脚与非连接器端点不变。详细布线评价见规则与布局文档。

## 网表/ERC

```text
kicad-cli sch export netlist --format kicadxml --output <报告>/before.net <根原理图>
kicad-cli sch erc --format json --severity-all --output <报告>/erc.json <根原理图>
```

按本机 `--help` 调整。比较组件、逐针网络、pinfunction/类型、封装和值；网络code不稳定。自动unconnected网名变化单独解释。

- ERC比较类型＋对象/引脚＋描述，不仅总数；错误替换成另一个错误可能数量不变。
- PWR_FLAG表达驱动约定，不是真电源；不要掩盖电源漏接。
- 不批量把pin改passive清零ERC。
- 解析成功不保证可读性；按需导出SVG/PDF检查文字、脚号、导线与分页。HTML报告可嵌SVG，不用截图替代源数据。
- 检查逐器件注释覆盖清单与原理图可见内容一致；纯注释变更应保留元件和值/封装/网络，不能顺便“修正”电气设计。

## BOM

从根实例/网表生成，含位号、值、封装、数量、MPN、DNP/非采购、来源和待定项。区分英制0603与公制0603，连接器性别/脚距/贴片或插件型式逐项确认。

裸铜测试盘、示波器双触点、焊接跳线可能无实体采购件，合理标记，不强填料号。LCSC编号与制造商MPN分列，不编造包装后缀、库存和可购买性。

最后明确“原理图已改／库已改／PCB是否同步”，附变化集合与验证，不把待同步飞线说成完成。
