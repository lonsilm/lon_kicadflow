# 检查、差异验证与PCB审查报告

## 确定检查对象

记录根原理图、根PCB、项目文件、版本、保存时间、SHA256。正在编辑的GUI与保存文件可能不同；旧报告不作为当前事实。无需修改文件也能检查的工作立即进行。

新报告使用独立目录，不覆盖旧证据。按任务运行适当检查，全部通过后不反复全量重跑，除非源文件变化、新失败或仍有具体疑问。

原生几何辅助器（可选，不依赖GUI）：

```text
<匹配KiCad的Python> <SKILL>/scripts/capture_pcb.py <PCB> --output <新的geometry.json> --connectivity
```

输出板级焊盘有效多边形、轨迹/过孔、保存填铜、轮廓及原生连接图检查；使用mm和闭合GeoJSON环。公开API随版本变化，遇不支持的方法先检查本机签名再适配，不把缺数据默认为无问题。

辅助器的 `ground_regions` 使用精确网名 `GND` 作常见筛查；其它名字如AGND/PGND仍在全部zone几何中，应按实际地网集合审查，不能遗漏后就宣称所有地平面完整。

```text
python <SKILL>/scripts/kicad_ops.py snapshot <工程> --out <新报告>/before.json
python <SKILL>/scripts/kicad_ops.py inspect-board <PCB> --detail --out <新报告>/inventory.json
python <SKILL>/scripts/kicad_ops.py check <工程> --cli <CLI> --output <新的check目录> --parity
python <SKILL>/scripts/kicad_ops.py compare <before.json> --out <新的delta.json>
```

多个根页/PCB时显式 `--schematic` 和 `--board`；子页不是第二根页。`check`在严格只读方式下不重铺铜、不保存，不会“修好再检查”。

## DRC/ERC的三个结果

1. 工具是否执行成功、报告是否完整可解析。
2. 有哪些违规、排除项、未连接和源/板不一致。
3. 电气上是否可启动/稳定、制造上是否满足所选工艺。

这三者不能互相替代。CLI默认可能在有违规时仍返回0；脚本保留全部报告并按类别统计，不能把returncode=0写为零错误。使用 `--exit-code-violations` 时区分“违规退出”与解析失败；不把所有非0都当工具坏了。

JSON结构也不相同：某些版本ERC把违规放在 `sheets[].violations`，DRC则在根 `violations`。辅助器分别处理；未知schema必须报无法统计，不能因根键不存在默认零违规。报告中的ignore/exclusion与included_severities一起披露。

## DRC分类与优先级

| 类型 | 要分析什么 |
|---|---|
| 短路/净距 | 具体对象、网络、层、最近几何与有效规则；是否真短路、误网或过旧铺铜 |
| 未连接 | 端点、实际路径、铜区填充、悬空stub；不能只看飞线可见性 |
| 钻孔/孔环 | 钻孔到铜、孔到孔、外径环宽、槽、板边；不是一种“间距” |
| 板框 | 闭合、自交、重复、槽/内切、板外对象 |
| 规则/库不符 | 规则优先级、网类、局部覆盖、用户有意改封装与库的差异 |
| courtyard/丝印 | 装配可达/碰撞、文字压铜；区别于电气失败 |
| 孤岛/悬空铜 | 是连接受限、无效小岛、故意屏蔽，还是确需清理；不擅自删除 |
| parity | PCB/原理图具体位号、脚号、值、封装和网络差异 |

违规严重级别来自当前项目配置，可能有ignore/exclusion；审查时披露排除项。不要调整严重度让报告好看。

## 源与板逐端点一致性

- 当前根网表组件集合与PCB真实封装集合双向比较，处理机械孔/非BOM/无电气图形。
- `(ref,pin)→net` 与pad号比较，保留多pad同号、无编号机械pad的语义，不能把它们误计成多个信号触点。
- 比较值、封装ID及实际焊盘几何，必要时UUID/实例路径；footprint ID相同不保证嵌入内容相同。
- 多个同号焊盘、堆叠符号、多unit需要专门处理；辅助 `netdiff` 遇重复端点会拒绝，不能静默覆盖字典项。
- 改网后原铜即使“位置没动”也可能接错脚；必须重检查几何接触/短路。
- 命名相同不保证连接，命名变化不一定物理变化；有意rename应单列映射，不用数值netcode比较。

## 保护对象验证

只读：前后源哈希一致。范围修改：获授权文件可变，其他文件哈希一致，并用语义比较核对修改对象范围。

例：

- 只加电容：旧组件记录、旧逐针网表和原封装/值/MPN不变，新位号只增加指定支路。
- 只改3D：除模型节点外源文本/AST一致，焊盘、铜线、过孔、位置和net不变。
- 只改网类：工程JSON仅目标字段变化，PCB/原理图不变，再用原生有效规则核查。
- 只重排J5：其它连接器、MCU脚和所有固定触点不变，允许信号集合保持双射。

备份用于授权恢复，不自动写回。用户同时改文件导致哈希变化时，不把它称为自己没改动，也不恢复旧文件。

## 地平面和回流检查

先取得真实叠层和铜区的**填充结果**，不从zone边界或图层名猜。`inspect-board`只做库存，不是精确几何引擎；需要更深分析时用原生 `GetFilledPolysList`、`GetEffectivePolygon` 等本机支持的接口。

可输出GeoJSON/JSON，再用可用的几何库或原生多边形工具分析：

1. 每层主GND多边形、孔洞、岛、最窄颈、实际连接到GND焊盘/过孔的路径。
2. 高di/dt回路的实际面积、两侧铜、并行同网铜区与过孔，而不是只用一条线宽估计载流。
3. 每条重点信号的相邻参考层覆盖、跨槽区间、换层回流点、最近接地路径。
4. 去耦GND到对应地球/平面的回路；最近过孔的欧氏距离只作筛查，未必最短实际导电路径。
5. PMIC/功率器件EP内是否真有热过孔，via是否属于GND、通到哪层，不能把其它网的孔算进去。

多边形面积不等于高频参考质量；无直流孤岛也可能有长绕路。几何库缓存/坐标变换/采样分辨率都要验证，必要时与已知pad中心/原生连通性做交叉检查。

## 布局审查的具体结果

每条问题至少包含：位号/网络、层、坐标或焊盘、当前测量值、要求来源、建议动作、实际影响。优先级以失效影响为准，不把丝印与内核稳压不确定并列第一。

避免过度结论：

- 元件中心距只是筛查，不是完整电源回路长度。
- 一个MOS缺低VGS规格是“未证明适配”，不自动推断必坏。
- 没有明显短路不等于可以保证启动。
- DRC报库不符不一定该回退用户封装，先核实际焊盘。
- 暂未进行3D碰撞、阻抗计算或实测时明示，不把渲染成功替代这些检查。

## HTML报告

用户偏好自包含HTML。按实际复杂度制作，别为小查询强行出长报告。

推荐信息：当前结论与适用范围、当前板快照、最高优先级问题、逐项建议、电源/地/信号审查、完整DRC分类表、证据链接和局限。可加搜索/优先级筛选，表格窄屏可横向滚动；动态内容必须HTML转义。

无外部CDN或追踪，无必须联网的字体/JS。需要图时用内嵌SVG/交互HTML或明确来源的矢量视图，不仅放PNG。HTML应包含主结论和必要细节，不依赖另一个Markdown才读得懂。检查链接存在、问题数量与原始JSON一致、JS语法与基本筛选行为；提供源数据而非编造检查。

## 打板建议

分别表述“可以作为试验首板制造”“关键风险已确认”“保证焊后即用”。用户愿意试首板时，直接给决定性风险和建议，不要求所有外观优化完毕；明确短路/错误电压等实际阻碍则不能淡化。导出包的完整性与硬件工作保证分开。
