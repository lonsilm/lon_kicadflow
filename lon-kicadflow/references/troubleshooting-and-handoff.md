# 排错、恢复、清理和跨机器交接

## 排错表

| 现象 | 先确认 | 合理下一步 |
|---|---|---|
| CLI找不到 | PATH、显式安装路径、版本 | probe/--cli；不全盘乱搜或改系统PATH |
| import pcbnew失败 | Python路径、位数、DLL版本 | 用匹配KiCad绑定；纯文件任务继续用标准库 |
| IPC连接拒绝 | 编辑器是否开、API支持/设置、端点 | 只读磁盘继续；不启动替代服务假装官方IPC |
| IPC位置与画面/多边形不符 | 缓存ID、相对/绝对坐标、层模板 | 公开ID重读、非对称pad校验；不人工平移掩盖 |
| F8/更新库找不到封装 | fp-lib-table、库昵称、uri、KIPRJMOD | 修正授权的源/库依赖，未授权不执行F8 |
| 3D缺失/离板/反面 | 路径、文件类型、单位、原点、层翻转 | 核实机械外形与变换，不镜像电气编号 |
| 原理图线看着接上但网表没连 | 网格、端点、标签作用域/旋转 | 精确坐标和根网表，不能只加结点掩盖 |
| 规则已改仍布不进 | 预设/网类/最小/局部规则、孔到铜 | 查看有效约束和几何必要条件，不继续盲降铜净距 |
| DRC总数少了但出现新短路 | 类型/对象变化、改网旧铜 | 逐违规差异、端点/几何验证，不看总数宣称改善 |
| 用户文件突然变了 | 保存时间、锁、并发编辑、源哈希 | 停止依赖旧派生结果，重读；不恢复自己快照 |
| 导出少内层/孔错位 | 源层数、Gerber/钻孔原点、镜像 | 同源同原点重导出，不手工平移修Gerber |
| 清理后库/网表失败 | 删除清单与库表依赖 | 仅按已知备份恢复缺失依赖，用户板不回滚 |

## 文件级安全修改

读取当前源→定位对象→最小修改→原生解析→语义差异→保护哈希。S表达式用结构解析；JSON保留无关字段；报告输出不能覆盖工程源。写入前备份确切原件并记录来源，不使用日期相似的旧文件当备份。

失败时停止扩大修改，先区分环境问题、语法损坏、电气问题与并发用户编辑。可以修复自己产生的授权源修改；不能借“回滚”恢复整个用户板，尤其PCB只读时。

## 备份与清理

- 哈希清单不是备份；需要恢复时保存真实文件和依赖。
- 自动备份、历史恢复快照、源库、模型、手册、固件、选型证据和有效最新报告不默认删除。
- 候选清理列路径、用途、体积、依赖、是否可重建。只删明确过时派生文件和缓存；不确定保留，不把整理目录当授权删工程。
- 递归删除/移动前解析绝对目标并核对在授权目录；Windows用同一shell端到端原生命令，不把路径枚举交给另一shell字符串拼接。
- 清理前后保护源哈希相同，根网表仍可导出，组件数/关键端点一致。记录manifest，不只说释放多少空间。

## 跨机器携带工程

skill与工程是两份东西：skill提供方法/脚本，不包含用户PCB和第三方全部库。完整工程迁移收集：

1. 根pro/sch/pcb及所有引用子页、自定义规则。
2. 项目库表与其真实文件、继承符号依赖、3D模型和必要字体/图纸。
3. 精确BOM、关键原厂资料、设计输入、固件/初始化参数和许可。
4. 新机KiCad版本、有效环境变量、CLI路径、Python/API能力探测。
5. 哈希、最近验证报告与已知未完成项。

扫描库表uri、模型路径和符号属性中的绝对路径；优先项目相对路径。检查路径大小写（Windows不敏感而Linux可能敏感），保留中文UTF-8文件名，ZIP中使用相对路径。不要迁移旧机器的API端点、用户锁和窗口几何当必要依赖。

## AI_HANDOFF.md建议内容

交接文档应是一份当前入口，不无限叠加“最新”导致互相矛盾。更新时保留可核实历史链接，不用历史结论压过当前原始数据。

```text
工程入口、根文件与真实版本
当前用户目标和已授权/禁止范围
当前保存源哈希、读取时间、数据来源
目前实际层数/组件数/网表与PCB同步情况
已做的变更与验证证据链接
最高风险及尚未解决事项
启动/供电/下载/时钟/固定引脚保护约束
跨电脑依赖与可重现命令
下一步具体动作，哪些是建议、哪些已完成
此前错误结论的明确纠正
```

链接指向实际存在文件。禁止复制旧计数并称当前；记录“截至某哈希的检查”。为新AI准备提示词不等于已经连接/发送给外部AI；未授权不向别的任务/人员发消息。

## 沟通和结束

中文直说当前结果、剩余实质问题与下一步；不反复解释工具内部流程，不把用户已有授权再问一遍。需要等待用户保存时说明有证据的覆盖风险及操作来源，继续独立分析。审查交付优先HTML，制造交付ZIP；工程没改就明确没改。
