# 实际创建、摆放与修改PCB

本文用于用户已授权PCB编辑/新板绘制的任务。**工程AGENTS若禁止写PCB，不因本流程而解除。** 只读审查不要执行以下保存/铺铜动作。

## 选择执行方式

1. 当前编辑器打开且官方IPC有必要能力：使用已安装公开API，依据对象UUID修改，在提交前后重读；不要让离线文件和内存同时竞争。
2. 新工程或编辑器已关闭、且工程没有“只能IPC”等额外限制：可用匹配版本pcbnew或局部结构化源修改，在可恢复基线/隔离副本验证后按授权范围落盘。
3. 缺少路由/导入接口：先完成可做的原理图、规则、库、摆放建议或已验证铜对象创建；说明尚未完成交互推挤/自动同步。不能编造CLI导入网表或路由命令。

不要为“工具比较方便”在第三方服务里复制出平行工程。持久保存必须符合当前作用域；一轮只改3D的授权不允许顺便更新封装和焊盘。

## 新板的准备顺序

- 确认根原理图已被原生解析，注释/封装指派/网络有效。
- 确认板框、安装孔/连接器机械坐标、层数和制造规则。
- 导入/创建元件实例时保留到原理图实例路径的关联，不能只让位号看起来相同。
- 定义并核对网名、脚号与网络code映射。code由板管理，不能跨文件搬旧数字。
- 先固定机械对象，再按电气回路摆放；记录正反面、旋转和高度。
- 约束明确后才布线，优先关键电源、时钟/高速/模拟，再普通信号。

## 原理图同步的真实边界

“Update PCB from Schematic”/F8是会改PCB的操作；热键可自定义。现代CLI通常没有能原样替代该对话框全部行为的通用同步命令。

可用官方公开接口时，先确认是否覆盖添加、移除、重编号、更新网和路径关联。不能只 `FootprintLoad` 一批器件，就说F8同步完成。离线实现必须显式建立实例路径和逐pad网映射，并与根网表验证；多unit/机械孔/无号机械pad单独处理。

更新已有板时检查：

- 关联路径/UUID是否一致；不要重复增加已有安装孔或同位号封装。
- 用户有意修改的焊盘和封装是否会被库覆盖；未要求更新则保护。
- 变更网络后旧铜是保留、重连还是待处理；不得自动删全板线。
- 更改pinout/奇偶列后旧铜可能接触其它pad，必须运行短路与parity检查。

## pcbnew动作片段

下面是**示例片段，不是完整同步器/自动布线器**。仅用于新项目/获授权副本，先检查本机docstring。`board`、库目录、网、实例身份与输出目标由实际任务取得，不硬编码用户工程路径。

```python
import pcbnew as p

def point(x_mm,y_mm):
    return p.VECTOR2I(p.FromMM(x_mm), p.FromMM(y_mm))

# b = p.LoadBoard(authorized_source)
# 或新项目的 b = p.BOARD()；层数/厚度/规则需另行设置验证。

# 添加准确库封装。
f = p.FootprintLoad(str(pretty_directory), footprint_name)
if f is None:
    raise RuntimeError('Footprint could not be loaded')
f.SetReference('R1')
f.SetValue('1k')
f.SetPosition(point(100,100))
f.SetOrientationDegrees(90)
b.Add(f)

# 网络对象要复用板上现有同名网络，不能每次重建产生重复。
net = p.NETINFO_ITEM(b,'EXAMPLE_NET')
b.Add(net)
pad = f.FindPadByNumber('1')
if pad is None:
    raise RuntimeError('Missing expected pad 1')
pad.SetNet(net)

# 直线对象不会自动避障、推挤或维护差分/等长。
track = p.PCB_TRACK(b)
track.SetStart(point(100,100))
track.SetEnd(point(105,100))
track.SetWidth(p.FromMM(0.25))
track.SetLayer(p.F_Cu)
track.SetNet(net)
b.Add(track)

via = p.PCB_VIA(b)
via.SetPosition(point(105,100))
via.SetWidth(p.FromMM(0.6))
via.SetDrill(p.FromMM(0.3))
via.SetLayerPair(p.F_Cu,p.B_Cu)
via.SetNet(net)
b.Add(via)
```

上例坐标/尺寸只说明API形状，不是推荐器件位置/信号规则。真正走线应从实际pad几何中心/逃线出口取得起终点，考虑pad边缘、层、net和规则。新脚网映射、原理图实例身份、焊盘几何和未连网在此示例未完成，不可直接作为可投板项目。

保存获授权副本可用本机 `p.SaveBoard(output,b)`（检查签名和返回值），随后重新载入并CLI检查。**不在根PCB只读任务使用此调用，不通过保存再恢复规避。**

## 翻面、旋转和身份

`SetLayer(B.Cu)`并不总等价完整翻面；封装pad层集、文字、模型和朝向也需改变。使用本版本正确Flip操作并核对结果；KiCad10某API需要 `Flip(centre, flip_direction)`，旧代码的布尔参数不能盲用。

- 旋转单位使用明确的degrees或EDA_ANGLE，别将十分之一度、弧度混用。
- 获取pad全局坐标后不再手动镜像；从库的局部pad坐标计算时才做完整变换。
- 移动保留已有对象UUID；新对象不能复用原UUID。
- 手工设置Reference不自动创建原理图path关联；用本机支持的路径接口或结构字段建立，再核parity。
- Locked表示编辑保护，不意味着电气正确；用户锁定对象在布局优化中作为固定约束。

## 板框、铜区与填充

板框在Edge.Cuts形成唯一正确外轮廓及明确内切孔，线弧端点精确闭合，无重复/自交。不要用Dwgs.User矩形充当制造板框。板框几何修改也属于PCB写入。

铜区需要网络、层集合、轮廓、净距、热连接和孤岛策略。API的Zone/Outline调用随版本变化，读取本机签名和已验证样例后创建。不把只有zone边界的板说成已经铺好铜。

**正常授权设计阶段**可用本机公开填充器如 `ZONE_FILLER`，或本机CLI支持的重铺铜流程；先在副本验证，明确保存。**只读审查/导出阶段**保持保存填充，不自动调用填充器。

规则区/keepout有“禁止走线/过孔/焊盘/铜区”等分项，不必全部禁；敏感晶振区与机械禁布按实际要求。模型中不知道具体flags时保守处理并披露，不能反过来说实板禁止全部对象。

## 布线实现与验收

自写轨迹创建不能等同KiCad交互推挤路由。以线段/圆弧生成路径时，每次检查实际障碍膨胀、孔到铜/孔到孔、有效净距、层转换和返回路径，避免只在栅格中心上认为安全。

可逐组增量验证：关键电源回路→启动时钟/调试→差分/高速/模拟→其它信号。相同网铜区可并联导电，分析线宽时纳入；不同网铜与keepout需正确阻挡。

接受标准：预期网络与实例集合、实际连接、无新增短路/间距/孔违规、授权范围外对象不变、填铜状态明确、3D机械约束复核。报告未完成的等长/阻抗/装配事项，不把试布路径数当作完整板。

## 一个从零项目的闭环

1. 新建最小工程，记录电源/接口假设。
2. 选择准确符号封装，绘制有明确网名和测试入口的功能页。
3. 根网表/ERC；核关键脚号与供电条件。
4. 建真实板框/叠层/规则，导入或正确创建关联的PCB实例。
5. 摆放关键电源回路与去耦，再摆连接器与其它器件；核机械高度。
6. 关键网优先布线，明确可重布范围，增量DRC/网络检查。
7. 授权状态下重铺铜并保存；完整检查连接与参考地。
8. 校核原理图/PCB/BOM/坐标，出审查HTML及制造ZIP。

每步做到实际成果可验证，再报告完成；接口缺口或需用户动作的部分明确列出，不能因为流程写在文档里就宣称软件具备自动完成能力。
